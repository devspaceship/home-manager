# Release Readiness

Treat release preparation as an evidence-gathering task, not a request to publish automatically.

## Workflow

1. Determine the target version, release branch, and repository release convention.
2. Inspect changes since the previous release or requested baseline.
3. Verify version files, changelog or release-note requirements, and the relevant test suite.
4. Draft concise user-facing release notes from confirmed changes.
5. Ask before tagging, pushing, publishing, or creating a hosted release.

## Output

Report `Readiness`, `Evidence`, `Release notes draft`, and `Required actions`.
